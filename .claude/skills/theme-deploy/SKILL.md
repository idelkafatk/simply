# Выкладка темы simply на idel.blog

Тема собирается gulp'ом и загружается в Ghost через Admin API (`yarn deploy` = загрузить zip и сразу активировать). Страницы сайта Cloudflare держит в кэше **сутки** (правило «Cache public HTML»), а смена темы **не вызывает вебхук** Ghost — Telegram-бот сбрасывает кэш только при публикации, правке, снятии и удалении постов. Поэтому без шага 6 читатели сутки видят старую тему.

## Правила

- Всё, что уходит наружу — `git push`, `yarn deploy`, сброс кэша — только после явного «да» на показанные команды (глобальный CLAUDE.md). Одно «да» покрывает ровно показанный список, не больше.
- Перед выкладкой показать, что меняется: `git diff --stat` и суть правок.
- Картинки темы класть в `src/img/…`, а не только в `assets/images/`: сборка копирует `src/img` поверх `assets/images` и молча вернёт старые файлы.
- UI-правки до выкладки проверить скриншотами: десктоп, телефон 390px, тёмная тема.

## Порядок

1. **Проверить рабочее дерево.** `git status --short` — в коммит идут только файлы этой задачи.

2. **Собрать.**
   ```
   cd ~/pet/simply && yarn prod
   ```
   Получится `dist/simply-v<версия из package.json>.zip`. Заглянуть внутрь (`unzip -l`), что изменённые файлы там и картинки новые (сравнить md5 с `src/img`).

3. **Показать план и получить «да».** Список ровно такой:
   ```
   git add <файлы> && git commit -m "…"
   git push origin master
   yarn deploy                      # загрузка zip + активация темы в Ghost
   POST /zones/f7d640ebb73f5a375381c544c9b15f83/purge_cache {"purge_everything": true}
   ```

4. **Коммит и пуш** в `master` (github idelkafatk/simply).

5. **Выложить.**
   ```
   cd ~/pet/simply && yarn deploy 2>&1 | grep -vE '[0-9a-f]{24}:[0-9a-f]{64}'
   ```
   Ключ Admin API в выводе вырезать. В логе должны быть `uploaded` и `activated`.

6. **Сбросить кэш Cloudflare** — обязательно, сразу после `activated`. Через `mcp__cloudflare-api__execute`:
   ```js
   async () => cloudflare.request({
     method: 'POST',
     path: '/zones/f7d640ebb73f5a375381c544c9b15f83/purge_cache',
     body: { purge_everything: true },
   })
   ```
   Ответ `success: true`. Сбрасывается весь сайт: каждая страница один раз на каждом узле (HKG/NRT/KIX для Кореи) откроется медленно, дальше снова из кэша — это нормально.

7. **Проверить живой сайт.**
   ```
   curl -s https://idel.blog/ | grep -o 'assets/[^"]*?v=[^"]*' | head    # новые ?v= у main.css/main.js
   for i in 1 2 3; do curl -sI https://idel.blog/ | grep -i '^cf-cache-status'; done   # MISS, затем HIT
   ```
   Для изменённых файлов (картинки, иконки PWA) сравнить md5 живого `/assets/…` с исходником. Открыть сайт в браузере и посмотреть главную и пост на телефоне и в тёмной теме.

8. **Сообщить**, что выложено, какой коммит, что кэш сброшен и что проверено.

## Когда ещё сбрасывать кэш

- Ручная смена настроек Ghost: меню, название и описание сайта, логотип, иконка, профиль автора (соцсети, город), code injection. Вебхука на это нет — после правки пользователя сбросить кэш шагом 6 (тоже после «да»).
- `routes.yaml` загружает только пользователь вручную: Ghost Admin → Settings → Labs → Routes (ключ интеграции туда не пускает). После его загрузки — сброс кэша и проверка `/`, `/notes/`, `/rss/`.

## Справка

- Кэш-правило: зона `idel.blog` (`f7d640ebb73f5a375381c544c9b15f83`), ruleset `05fa87d74f5c4a8bb6e7e697dfcdff8d`, правило `99cacce4ac7343208b04e27b90d149c5`. Кэшируются только GET с ответом 200 на сутки; ответы ≥300 (редиректы, 404, 5xx) не кэшируются никогда; мимо кэша идут `/ghost`, `/members`, `/api/`, `/webhooks/`, `/p/`, `/r/`, `/sw.js` и запросы с куки `ghost-members-ssr` / `ghost-admin-api-session`.
- Сброс при постах делает бот `~/pet/idel-blog-tg-bot` (`src/cloudflare/purge.ts`, токен `CLOUDFLARE_PURGE_TOKEN` в Dokploy). Если после публикации поста сайт старый — смотреть логи бота: строка `Cloudflare cache purged (…)`.
